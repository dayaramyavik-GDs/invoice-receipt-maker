# Invoice & Receipt Maker v0.1.1

First tested release: an offline-first Android app for sole traders, cleaners, tutors, tradespeople and market
sellers, plus an optional sync API.

## What's in it

**Works with no internet**
- Business profile with logo, VAT number, payment terms and payment instructions
- Customers and a saved items/services catalogue
- Invoices and receipts with itemised lines, quantities, prices and tax; totals in integer pence
- Automatic numbering (`INV-0001`, `REC-0001`), part payments, mark as paid, void, delete drafts
- Branded A4 PDF made on the phone and shared through Android's share sheet
- Dashboard (outstanding, overdue, received this month), filters and search, JSON backup export

**Optional cloud sync** (in builds with an API URL set)
- Email/password account, backup, and use on a second phone
- Edits to different fields on two phones are merged; payments are never lost; real clashes go to a review screen
- In-app account deletion

**Server**
- Node.js 24 / Express 5 API with bcrypt + JWT, Zod validation and rate limiting
- Docker image `ghcr.io/dayaramyavik-gds/invoice-receipt-maker-api:0.1.1`
- Kubernetes manifests (`k8s/base`, `k8s/production`, `k8s/local`) with zero-downtime rolling updates,
  autoscaling and health probes

## Tested on

- Pixel 9 Pro Fold, Android 17, in airplane mode (offline flows, share sheet, void/delete with native dialogs)
- Android 15 emulator as a second device (sync and conflict merging)
- k3s Kubernetes v1.34 (rollout under load with 0 errors, rollback, self-healing, autoscaling 2→6→2)
- Full results: [docs/test-plan.md](../test-plan.md)

## Download

`invoice-maker-0.1.1-debug.apk`: a **debug-signed, offline-only** build for testing. Install it by allowing
installs from unknown sources. Cloud sync is switched off in this build because there's no public API yet.
A Play-Store-ready signed build will follow once the API is deployed (see the M6 Release milestone).

## Known limitations

- Two phones issuing invoices while *both* offline can pick the same number.
- Public HTTPS deployment and a signed release build are not done yet (issues #19–#21).
